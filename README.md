# THEMADLIONS Projects

Web-based film production workspace for The Mad Lions. Dark mode, desktop first, works on phones and tablets.

**Phase 1 (this repo):** everything runs in the browser and is saved in that browser (localStorage). Works on GitHub Pages with zero backend.
**Phase 2:** Supabase (auth, Postgres, storage, edge function for the AI) so the whole team logs in from anywhere. Schema is already in `supabase/schema.sql`.

## What is inside

- Projects in six categories: Music Video, Event, Editing, Ad, Visuals, IV
- Script import: PDF, Word (.docx), Final Draft (.fdx), Fountain, plain text, or paste. Pages files: export to PDF first
- Event category: no script, breakdown or shot list; the Schedule tab becomes a Run of show (event days with timed blocks and owners, standard blocks from load-in to load-out), call sheets show the run of show and talent calls, and progress counts venue, crew, run of show, event days and recap deliverables
- Music tab (Music Video projects only): upload the song (MP3, M4A, WAV, private Supabase bucket; a WAV, AIFF or FLAC is converted to a 192 kbps MP3 on your own device before it goes up, so a 40 MB master becomes about 6 MB in storage and the master never leaves your disk; the encoder is lamejs, LGPL, kept as its own file under public/vendor/lamejs and loaded only when needed), waveform player drawn in the browser with click-to-seek and section loops, a Download button that saves the stored file to the device, several versions (master, playback, instrumental), and a song map: sections (intro, verses, choruses) with start and end times, lyrics, notes and the setups from the breakdown that cover each one; paste the whole lyric to create sections at once, mark times while the song plays, export the map for the editor. Lyrics from the audio with OpenAI Whisper (own key in Settings): either writes the lyrics and creates sections at the pauses, or only times the sections you already pasted by matching what it heard. The AI treatment breakdown reads the song map and links setups to sections
- Script revisions: every new upload or edited save keeps the previous version with its revision colour (White, Blue, Pink, Yellow, Green…), side-by-side compare, restore. Re-running scene detection matches scenes by heading so breakdown tags, shots and schedule survive, and changed scenes are flagged on the strips
- Scene detection in English and Greek (INT./EXT., ΕΣΩΤ./ΕΞΩΤ., DAY/NIGHT, ΜΕΡΑ/ΝΥΧΤΑ), characters, page eighths
- Treatment, concept and moodboard breakdown: upload a director's treatment, a concept in plain words, a PDF moodboard with images or reference photos; Claude groups the material into shootable setups (location, time of day, talent, wardrobe, props, art, effects, equipment, look, time estimate), lists locations, talent and producer notes, and can draft a first shot list. Built for music videos and commercials that never had a screenplay
- AI breakdown with Claude: props, wardrobe, vehicles, SFX, extras, flags per scene, plus reports by character, location and element. CSV export
- Production sheet (Breakdown > Sheet): the grid you used to rebuild by hand in a spreadsheet. Scenes down the page, characters across it, a dot where someone plays. Group the scenes by **set**, by **shooting day**, by **day or night**, or leave them in script order; each group shows its scene count and page total, and the bottom row says how many scenes each person is in. The scene and set columns stay pinned while you scroll sideways. Download .csv to open it in Google Sheets or print it
- Shot list per scene: size, angle, movement, gear, lens, camera, storyboard frames, list and board views, CSV and print
- Stripboard schedule: shoot days, scene assignment, industry strip colours, unscheduled pool
- Day Out of Days for cast (SW / W / WF / SWF / H) computed from the stripboard
- Share link: one tap turns the day's call sheet into a public link that opens on any phone without login. Because the link carries everyone's phone number and links get forwarded, Settings > Call sheets can put a **six digit access code** on every call sheet link: the code goes out with the link, the page shows nothing without it, and crew type it once per phone. Delivery, estimate and status pages take an optional code of their own from their form, laid out for mobile (big call time, location with directions, pinned note, everyone's call, scenes). Department requirements stay private. Sharing again after edits refreshes the same link
- Send message: the call sheet as a WhatsApp-ready message (whole sheet for the group, or a personal message per cast and crew member with only their call time and location), mail with everyone in Bcc, or copy. WhatsApp links on cast and crew cards
- Weekly backups (administrators, Settings > Data): once `supabase/backups.sql` is run, the database takes a snapshot of the whole workspace every Monday at 06:00 Athens time and keeps the last twelve, inside Supabase, no credentials anywhere. Back up now takes one by hand. Download turns a snapshot into the same file the Restore button reads, so a copy can live on your own disk; Restore puts projects, calendar items and the library back
- Finance overview statistics: a **Sort by** bar above the By project, By client, By category and By project type tables (Income, Expense, Profit, Margin, Share, Outstanding, Owed, Transactions, Name, plus High to low / Low to high) sorts all four at once; a click on any column heading does the same. The tables show how many transactions each row holds, its share of the year's income or expenses, and a totals row; the client table adds Outstanding (invoiced, not yet paid, gross). A **By quarter** table gives income, expense, profit and the VAT charged, paid and balance per calendar quarter, what the quarterly VAT return settles. The Profit tile compares the booked profit with last year's.
- Finance categories are yours to shape too: **Finance → Settings → Income & expense categories** (administrators). Two lists; click a name to rename it and every transaction and recurring item filed under it follows, and for an expense column the budget categories that land in it follow as well. Reorder, add, remove (a category with items on it asks where they go first), Reset to standard. Saves at once.
- Budget categories are yours to shape: **Settings > Budget** (administrators) lists the groups (Above the line, Production, Post-production, Other) and the categories in each. Click a name to rename it and every budget line already filed under it, in every project, follows. Add, reorder, remove; a category with lines on it asks where those lines go before it disappears. Each category names the Finance column a payment on it lands in. Reset to standard brings the built-in list back; lines under a category that no longer exists show as "Unlisted" in the budget rather than vanishing
- My work, Add job: **Project** comes first. Pick one and the client (or the project's title when it has no client), the description (the title) and the shooting date fill in from it: the latest day already shot, else the first one coming, else the project's start date. Anything you typed by hand stays; switching projects replaces only what the previous one filled
- My work to the budget: a job someone enters in their own My work **with a project** puts their fee into that project's budget as a line paid to them (category from their department when it matches, else Production staff). If the production already entered a line paying them, the new job is tied to that line instead (amount and paid state follow the line), and a second job on the same project is refused, so nothing is entered twice. A job that comes from a budget is never marked paid by hand: it turns to Paid when the payment is recorded (Finance, the budget's Pay, or Record payment in Team work), which writes Finance, the budget and the job at once. The job is linked to the line, so a payment turns it to paid. Members without Budget = edit go through `supabase/worklog_budget.sql`, a function that can add one line for themselves and nothing else
- Budget line paid to a team member: **Paid to** on a budget line lists the team (name and position from their profile) or "someone outside the team" with a free vendor name. Pick a member and the line goes straight into **their My work** as a pending job with the line's amount, the project, the client and a **work date** you set on the line. Change the amount and it follows; delete the line and the job goes. Record a payment from Finance or Pay and the job turns to paid on the day it was settled, with the method. The member sees only their own line, never the rest of the budget, and the job says "from the project budget". Administrators write into anyone's My work directly; a producer with Budget = edit needs `supabase/worklog_assign.sql` run once
- Tabs per project: a **new project opens with Overview alone**. Overview > Edit details > **Tabs** lists every tab the project's category offers; tap one to switch it on, tap again to hide it. Overview always stays. Changing the category brings its own tabs in switched off. Nothing is deleted, a hidden tab keeps its data and its page still opens from an old link. Projects made before this keep every tab
- Projects page: delivered projects leave the main grid. A **Delivered · N** chip at the end of the category row, in the inverse colour of the others, shows them alone, grey until hovered; the category chips count only what is shown. The heading counts active and delivered separately.
- Project cover image (compressed, stored in the project) shown on the dashboard card, the project header, the Overview and the call sheet; Overview progress bar with weighted stages per category (script, breakdown, budget, cast, locations, shot list, schedule, shoot days reported, post and delivery; Editing projects use cut, approval and deliverables), each stage linking to its tab; dashboard cards carry a thin progress bar
- Transcript from the audio shown in the Script tab of music video projects, with copy and "use as script text"
- Home: this week (shoot and event days, calendar items), needs attention (overdue tasks, budgets over cap, unpaid invoices for admins), all projects with progress, next day, open tasks and budget vs cap, counts by status and type, finance snapshot for admins
- Project files: uploads to a private Supabase bucket (50 MB per file on the free plan) with open and download, plus a cloud folder link per project (pCloud, Drive, Dropbox) for footage and masters
- Light and dark themes with five accent colours (Lion amber, Red, Slate blue, Lilac, Ink; Settings → Display, per device); the light theme is the default
- Call sheets laid out like a professional call sheet: company block with producer, director and key crew, big general crew call with a one-line message, day and date with weather, sunrise and sunset, shooting call / lunch / wrap, a pinned note everyone reads, and a location grid with set location, parking and nearest hospital

## Deploy on GitHub Pages

1. Create a new repository on GitHub (for example `themadlions-projects`).
2. Push this folder to the `main` branch.
3. In the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. The workflow in `.github/workflows/deploy.yml` builds and publishes on every push. The site appears at `https://<your-user>.github.io/themadlions-projects/`.

Routing uses hash URLs (`/#/p/...`) so it works on Pages without server rewrites.

## AI breakdown key (Phase 1)

Settings → AI breakdown → paste an Anthropic API key. It is stored only in that browser and calls the API directly. In Phase 2 the key moves to a Supabase Edge Function.

## Phase 2: Supabase (team logins, one shared database)

1. Create a project at supabase.com (region Frankfurt).
2. SQL Editor → New query → paste all of `supabase/schema.sql` → Run. Then the same with `supabase/storage.sql` (photo bucket) `supabase/library.sql` (company library), `supabase/todos.sql` (general tasks), `supabase/audio.sql` (song files), `supabase/files.sql` (project files), `supabase/finance.sql` (administrators-only finance) `supabase/chat.sql` (team chat) `supabase/notices.sql` (notices) `supabase/worklog.sql` (personal work logs), `supabase/drives.sql` (drives archive) `supabase/shares.sql` (public call sheet links), `supabase/activity.sql` (activity log), `supabase/deliveries.sql` (client replies on a delivery page) `supabase/share_access.sql` (only members with the Share permission may send delivery links) `supabase/share_track.sql` (counts openings, closes a link by hand or on a date), `supabase/estimates.sql` (lets a client accept a cost estimation), `supabase/share_pin.sql` (an access code on a public link) `supabase/notices_ack.sql` (a notice can only be edited by whoever sent it; Got it goes through a narrow function) `supabase/worklog_assign.sql` (a budget line paid to a colleague reaches their My work even when the person editing the budget is not an administrator) `supabase/worklog_budget.sql` (a job in My work adds the person's own fee to the project budget), `supabase/chat_rooms.sql` (chat rooms: project rooms, groups, direct messages, replies, attachments), `supabase/chat_project_members.sql` (an administrator can take people out of a project's conversation) and `supabase/backups.sql` (weekly snapshots of the workspace with pg_cron, kept in a backups table; if it says pg_cron is not available, enable the extension from Database > Extensions first).
3. Authentication → Providers → Email: keep it enabled; turn **Confirm email** off if you want teammates to sign in immediately.
4. Project Settings → API: copy the Project URL and the publishable (anon) key into `src/lib/supabaseConfig.js`, commit, push. The site rebuilds in remote mode.
5. Open the site, create your account. The first account becomes the administrator and the workspace is created automatically.
6. Settings → Storage → "Import them into the team workspace" moves the projects from this browser's local mode into the database.
7. Team → Add teammate: enter their email and permissions. They create an account with that email and land straight in the workspace.

Data model: each project is one JSON document (`projects.data`), events one row each, members and invites per workspace. Row Level Security enforces workspace membership, per-project access and edit rights; per-module view/edit levels are applied by the app. Live updates come through Supabase Realtime.

The AI key stays in each browser (Settings) for now; moving it into a Supabase Edge Function is the next step.
